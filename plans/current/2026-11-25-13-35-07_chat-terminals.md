# Chat terminals

Key: `[ ]` pending task, `[x]` completed task, `[?]` needs validation, `[-]` closed task

## Outcome and scope

Extend the Phase 11C owner workspace and shared chat harness. A user can drive a terminal while discussing its output in the same conversation. Preserve existing per-project grants, device authentication and controller handoff. The terminal host owns processes and access decisions. The chat owner may be on another device. Xavier qualification and remote installation are later work.

- [ ] In both chat surfaces put 💬 chat, ↔️ split and 🖥️ terminal beneath the session header. Reuse the draggable divider. ## Evidence and stopping condition

The existing Linux PTY has private temporary storage, a read-only checkout and no network. Other platforms can act as remote clients. Existing chat tool dispatch supports read-only operations. An interactive chat emulator changes the MVP boundary in README and ROADMAP; reconcile those contracts on implementation. Qualification requires observed UI and runtime behavior, including permission enforcement. A plan or a rendered button is insufficient evidence.

## Qualification checkpoint

The three shipped permission choices share the existing Linux PTY boundary. A live disposable shell test covered read-only denial, one-time approval, automatic dispatch in Yolo, changed arguments, revocation, output, a nonzero exit code and duplicate delivery. The worker API integration test exercised project and global chat suspension, callback correlation and model continuation against two independent authenticated loopback workers. The standalone headless chat retains its original tool set.

Rendered verification used 1280 × 800 and 390 × 844 surfaces. The split view wraps transcript content within the selected column and the composer spans the available width. Local screenshot evidence is under `.tmp/chat-terminals/`. Agent commands use a new isolated process per run. Xavier provisioning is a separate operation and requires a network-capable installation path.

Canonical publication and device evidence are recorded by the build in `releases/verified.json`. Physical cross-device use of the new chat controls requires a separate operator exercise.
