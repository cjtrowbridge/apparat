# Personal cluster implementation

Key: `[ ]` pending task, `[x]` completed task, `[?]` needs validation, `[-]` closed task

Bound to the [Phase 10 cluster milestone](../../ROADMAP.md#personal-cluster-governance-and-queue-sync) and the Phase 13 queue protocol. Existing device identities, SQLite roots, grants and APK signer survive upgrade. Route compilation, qualification and delivery through the normal host pipeline. Use the real personal identity, primary Pixel profile, and installed trashcan0 for hardware acceptance. Preserve their credentials and ownership. Destructive cases belong in automated tests. The owner authorized a subsequent real claim of the installed trashcan0 service. Credentials and recovery files belong in local protected input only.

1. [ ] **Personal identity.** Create or restore a password-encrypted portable user identity distinct from the installation key. An OS credential may unlock a local copy. Bind an editable screen name and authorized device public key with user signatures. Prompt only for missing state; provide explicit cancellation and recovery. Never create a user on a headless service. Test legacy roots, duplicate names, wrong passwords, lost-device removal and owner-key compromise/rotation.
2. [ ] **Personal pairing.** Discover an explicitly opened session on an allowed interface. Use reviewed password-authenticated key exchange, mutual key confirmation, bounded retries, expiry, target binding and owner confirmation on both screens. Transfer only the password-encrypted user bundle, signed profile, device authorization and verified initial cluster snapshot. Preserve independent device keys. Verify wrong code, replay, cancellation, no plaintext secret in storage or logs and remote-host substitution.
3. [ ] **Claim and authentication.** Learn the selected worker fingerprint on first contact and retain it for reconnections. Authenticate the saved personal and device keys through the worker challenge. Use scoped HTTPS and signed proof binding the claimant user, device, target, cluster, operation and challenge. Atomically admit exactly one first approved admin. Subsequent verified users start pending. Implement short-lived credentials, public key lookup, protected JSON handlers and current authorization on every call. Retain the owner-only administration route and scoped hosting guarantees.
4. [ ] **Policy.** Store cluster owners, policy authority, users, device authorizations, node-local and cluster-wide roles, admission state, groups, pool grants, and pool/service membership in SQLite. Keep private keys outside SQLite. Any current cluster admin may sign commands; one designated device orders them. Validate scope at commit, reject stale/conflicting edits and duplicate commands with changed contents, protect the last admin, and record immutable receipts. Define owner-authorized handoff with a monotonic authority epoch, a single successor and an explicit lost-authority recovery procedure. No writable key-directory authorization path.
5. [ ] **Replication.** Commit mutation, event and stream head atomically. Hydrate heads at startup. Authorize each requested stream and view before comparing in-memory heads. Return bounded pages or a verified snapshot when the cursor predates retention. Verify chain continuity, cluster/epoch and signer; persist changes and cursor together. Expanding privileges requires a fresh authorized snapshot; narrowing privileges invalidates cached views. Notify peers after commits. Batch by peer, coalesce duplicate triggers, jitter and back off. Default reconciliation to 300 seconds in editable policy. Trigger initial sync on pairing, reconnect, foreground and Cluster entry. Track committed, applied and enforced revisions separately.
6. [ ] **Queue slice.** Implement one harmless capability. Use one pool_tasks table, attempts and per-slot artifact references. Commands carry stable IDs; owner timestamps admission and assigns ordered queue revisions. Keep prompt/inputs immutable. Check permission, limits and service eligibility at admission and dispatch. Atomically claim work with a fenced lease. Retry after expiry; validate the active lease, signed result and artifact bytes before publishing success. Support cancellation, bounded worker wait, late/duplicate completion, restart, per-user result reads and privacy-filtered cursors. Protect artifact reads independently of hashes. Test automatic updater admission and drain across all of a worker's pools.
7. [ ] **GUI and hardware.** Populate Cluster Devices from persistent authenticated worker records, with discovery first and stable device identifiers. Retain the Routing, Tasks and Inference Types mock sections. Expose signed profile editing, personal pairing, host claim, user approval/block/admin, registration switch, pool membership/grants, polling interval, queue and enforcement status with the same keyboard, touch, controller and action-catalog routes. Verify on wide Linux and narrow Pixel. Claim installed trashcan0 using the owner's locally entered credentials. Pair Pixel, disconnect Steam Machine from the test path, perform a protected operation and admin edit, then verify incremental catch-up. Repeat with a separately authorized second admin, expired claim, revoked permission, duplicated event, offline completion and inaccessible artifacts. Measure unchanged response bytes, latency and zero event-table reads concurrently with backlog sync.

Later phases add inference, routing optimization, remote project browsing, leaderboard/chat publication, designated first-admin provisioning and optional messaging gateways. These do not gate the harmless job.
